# Shared selection contract

Selections contain local integer `min` / `max` bounds (inclusive, 0–4095), and optional exact `members` (XYZ arrays or packed local keys). Optional `regions` is an ordered list of bounded operands, each with `operation`: `replace`, `add`, `subtract`, or `intersect`, and optional exact `members`. Evaluation starts empty and applies each operand in order, intersected with the outer bounds. A region includes air unless it provides exact members. Empty member arrays select nothing. No dense air enumeration is required.

The same representation is accepted by `edit.brush` at `params.mask.selection`, and `selection.transform` directly at `params` beside `at`, `move`, etc. For `space: world`, all bounds and member XYZ arrays (including region operands) are translated by the confirmed world origin; packed keys are local-only. Existing policies, revisions, transactions and undo semantics still apply. Human viewport selections use this representation without changing voxel data or increasing the workspace revision.

```json
{"min":[0,0,0],"max":[30,8,30],"regions":[{"operation":"replace","min":[0,0,0],"max":[10,8,10]},{"operation":"add","min":[20,0,20],"max":[30,8,30]},{"operation":"subtract","min":[2,0,2],"max":[4,8,4]}]}
```

Viewport selection operands are transient. Saving object groups or generated voxel results uses the existing project persistence. Geometry/path and terrain generation accept this contract through `config.selection`, with `config.selectionMode` set to `volume` or `footprint` (`none` bypasses it). Footprint projects each operand onto XZ, then combines operands in order; it is not the projection of a previously evaluated 3D boolean solid. Complete guides are retained, while generated/support/earthwork operations are filtered. `construction.prepare` returns `value.scope` with mode, accepted and filtered counts. Saved geometry recipes retain this configuration. Feature extrusion/loft/sweep now use the same scope controls. A compound region's yellow bounding box is not its complete membership; colored operands and member outlines explain its construction.

Terrain `mode: slope` may provide local `slopePoints: [[x,groundLayer,z],[x,groundLayer,z]]` instead of numerical `y/slopeX/slopeZ`. The endpoint ramp projects along the XZ segment and clamps interpolation to [0,1], then rounds each target ground layer for voxel earthwork. Points must have distinct XZ positions; bounds and terrain protections still apply. Measurements are signed with respect to endpoint order.

Geometry `config.workplane` is `{origin,u,v,normal}` in local scene coordinates. Axes must be finite, unit, orthogonal and right-handed. Points remain world-oriented local scene XYZ; snapping and geometric constraints operate in the frame. `planeLock` confines controls to its plane when enabled. Guide recipes retain the frame, and automatic feature extrusion uses the referenced profile frame normal. Explicit world-axis feature-plane choices still take precedence. Workplane selection is transient until a guide/operation is confirmed.

Named plane methods: `workplanes.list` accepts optional `space: local|world`; `workplanes.put` requires `expectedRevision` (or a transaction) and `plane: {id?,name,frame,source?}`; `workplanes.remove` requires `id` and revision/transaction. Updates require an existing ID; duplicate names require an explicit update. `source.mode` is `snapshot`; unsupported follow modes are rejected. Reads and puts can convert frame origins in world space only with a confirmed project origin. Axes remain vectors. Existing sketch frames are not linked to library changes.

`workplanes.atCurve` accepts `guideId`, `station` in [0,1], optional expected revision/transaction and space. It returns frame, distance, totalLength, segment and snapshot provenance. Station is sampled-polyline arc length, not the Bezier polynomial parameter. Frame transport avoids arbitrary seed-axis changes along smooth sampled curves; sharp corners/cusps still have geometric tangent changes. This method is readonly.

Feature `operation: sweep`, `sweepMode: profile` requires one or more closed profiles (`profileIds` or inline `profiles`) and a rail (`pathId` or inline `path`). Optional `profilePlacement: asDrawn|center` controls offset; shape dimensions are preserved while aligning to the rail tangent. `hollow`, `thickness`, `caps` and `cut` apply. Missing `sweepMode` retains the old rectangle behavior; `rectangle` explicitly selects it. All feature operations accept `selectionMode` / `selection` as documented above. Sparse `guideGroups` are returned in previews and stored as display paths.

Multiple sweep profiles use normalized arc-length `profileStations` when specified; null entries infer station from reference position. Saved curve-station provenance supplies station hints in the GUI. Otherwise positions are inferred from nearest rail locations. Coincident multi-profile stations are rejected as ambiguous. `profileSamples` (default 64) matches perimeters; cyclic shifts and winding are aligned automatically. `smooth` eases interpolation, and outer station intervals retain their adjacent section.

Sweeps accept `closeFrame: false` to retain uncorrected closed-rail frames (correction is otherwise enabled). `seamMode: auto|manual` controls cyclic/winding matching; `profileSeams` entries follow selected-profile order and contain `shift` in [0,1] and optional `reverse`. Manual mode retains explicit correspondence. `construction.prepare` returns `closure` diagnostics when corrected. Direction closure is distinct from endpoint shape repair and self-intersection handling.

Profile sweeps accept `voxel: cube|smart` (default cube). Smart mode unions eight half-cell samples per voxel across segments and fits straight stairs/slabs. Optional `roles: {full?,slab?,stairs?}` provides explicit states; available names supplied by the shared resource catalogue allow family resolution. Generated `type`, `half`, `facing`, `shape` and `waterlogged` are preserved in project and NBT exports. Missing/unsupported patterns fall back to center-sampled full blocks or omit extra thin cells with reports. Cuts bypass fitting and erase whole voxels.

Profile sweeps accept `sweepOverlap: merge|stop` (default merge). Preview `overlap` includes sampled positions (up to 256), total count, policy and arc separation threshold. `blocked` is returned for stop mode when in-scope overlap exists, and commit/source-regeneration reject it. These diagnostics detect shared voxel-center membership between distant rail portions, not exact continuous curve/surface intersections.

Local-only immutable baseline reads: `scene.baselineManifest` indexes the current imported baseline and returns schema, baseKey, sourceHash, 16-cell chunk descriptors and original header without blocks. `scene.readBaselineChunks` accepts `keys: ["x,y,z",...]`, optional expectedRevision/workspaceId and returns items with `blocksData`, status and original palette indices. Backend requests page at 128 chunks; client pages larger reads and holds a bounded cache. Outside chunks contain no records; empty-records do not override source coverage masks or warnings. These APIs exclude current edits and do not replace `scene.readRegion` for canonical edited state. Capability is advertised only with an upgraded full local service.

Local current-checkpoint APIs: `scene.chunkSnapshot` synchronizes the current Worker delta/design to a versioned SQLite mirror. `scene.readStoredChunks` accepts chunk keys and optional expectedRevision/workspaceId, synchronizes the checkpoint and returns revision, digest, palette, size, origin and merged `blocksData`. Original palette indices are mapped into the current palette; null overlay state deletes the baseline record. New coordinates may extend the original footprint. The mirror is derived and does not replace current Worker transaction/edit authority. Backend checkpoints require CAS expectedStoredRevision and reject different data at one version.
