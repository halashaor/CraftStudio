现状证据学习对象实施顺序验收任务交互规格架构说明

真实地形始终是设计依据。人直接操作 3D，AI 可自由读写方块与状态；便利工具是可选能力。学习的是操作语义、反馈和数据组织，不把不同软件的菜单混在一起，也不把候选功能写成已实现。

人的设计路线

读取真实场地确认保留区域画草图／放参考模型预览形体决定落格与材料局部调整对照改动保存／施工／回读

Axiom — 官方文档已阅读；本项目涂改/条件原型验证通过；Axiom 上机观察待完成

一手参考资料

学习：选区、工具蒙版、涂改与新增分工、三维路径、状态保留

适配：共用选择和蒙版；材质替换保留楼梯/半砖类型与朝向；工具状态可理解

避免：不要求离线设计器必须运行游戏；不复制整套快捷键冲突

下一步：画笔只作用于指定表面和选区，比较撤销与确认行为

ObjToSchematic — 官网与转换/图集文档已阅读

一手参考资料

学习：模型/体素/方块分层、向导/工程两种入口、版本图集、调色板

适配：连续草图与模型保留为设计输入，方块为派生结果；导出类型清楚

避免：不以颜色匹配代替全部建筑设计；半砖和楼梯需按形态处理

下一步：研究旧版开源体素/网格结构，做同数据与同硬件比较

实施顺序与通过条件

先完成基础操作的语义，再扩展依赖关系和规模。阶段按任务验收推进，不按按钮数量推进；性能路线在实测后确定。

P0 · 基础操作与反馈 — 进行中工作项
  • 明确单点放置、连续绘制、已有表面涂改的分工
  • 统一选择、变换、预览、确认、取消与一次撤销
  • 可见的吸附/锁轴状态；输入不因预览重建失去焦点
  • 工具与快捷键只保留当前上下文需要的参数
验收
  • 放置沿一条路径拖动仍只放一个方块；画笔沿同一路径连续绘制
  • 涂改保留楼梯朝向与半砖上下层，撤销恢复原状态
  • 框选不旋转相机；导航不产生编辑；未确认的生成/变换取消后没有场景改动
P1 · 对象、选择与生成来源 — 进行中：已保存草图与直接派生更新已验证工作项
  • 基线、草图、连续模型、生成特征、方块对象分层
  • 可重新选择并编辑已保存的草图，而非只能新画
  • 记录来源与派生关系；局部手改可明确保留或独立化
  • 任意选择集合及选区蒙版，不把一切简化成包围盒
验收
  • 拖动已保存屋顶曲线，预览/更新对应屋顶而不改变原山坡
  • 改变源草图不会无提示覆盖已手改的门窗
  • 保存、重新打开后关系与对象名称保持一致
P2 · 三维建模与重复设计 — 部分实现，待系统验收工作项
  • 任意工作平面、三维曲线、拉伸、放样、路径生成
  • 形态感知的方块/半砖/楼梯落格
  • 组件定义/实例联动、阵列、镜像、独立化
  • 稳定的拖动预览、精确结果校准及错误定位
验收
  • 两种风格房屋分别在同一真实坡地上落位并导出回读
  • 一排窗户整体改型，再独立改一扇，其他窗不受影响
  • 调整屋顶坡度后朝向与半砖层位正确；缺素材不伪造方块
P3 · 素材、地形与施工准备 — 部分实现工作项
  • 资源配置包含 MC/Mod 版本、来源、许可信息与加载顺序
  • 完整素材库与项目可选调色板分开，AI 接口仍允许自由指定状态
  • 选区/表面/高度/邻接条件共用蒙版；真实地形作为约束
  • 分层查看、土方/材料统计、原始/新增/拆除显示
验收
  • 换用资源外观不改方块 ID、NBT 与工程几何
  • 仅涂改屋顶表面，地形、水面和受保护对象保持原样
  • 蓝图包含用户选择的真实地形范围，不生成替代山坡
P4 · 性能架构与两版分工 — 待基准与决策工作项
  • 记录实际输入到可见反馈的延迟，分开统计计算和显示
  • 先测现有分块网格与数据布局，再选择需要加速的热点
  • Lite 保留文件式设计并研究紧凑体素数据/WASM 热点
  • 本地版后端按区块管理和流式加载，后台执行大规模任务
  • 浏览器/桌面壳可以共享 UI；编译计算库可共享核心算法
验收
  • 同一数据、同一硬件、同一视角路径比较，不仅记录 mesh 计算毫秒数
  • 视口之外的区块不长期占用全部精细渲染资源
  • 连续拖动不积压旧任务；修改一小处不重建整个场景
  • 大场景修改、保存、重开和导出均校验实际方块数据一致
P5 · AI、游戏与完整工作流 — 接口部分实现，真实环境待验收工作项
  • AI 与人使用同一自由场景、事务、预览和保存能力
  • Java 多加载器桥接；文件导入独立于加载器
  • 能力协商、版本差异和无法转换的数据明确报告
  • 不做基岩版、不做完整产线仿真、不把 AI 限制为模板生成
验收
  • AI 从零生成建筑并在真实场地中继续手改，不依赖模板白名单
  • 在真实 Java 实例读取→设计→确认施工→回读→撤销
  • 四个桥接构建通过不能代替四个实际游戏环境施工验证

完整任务验收

  1. 在真实坡地上设计两栋不同风格房屋，保留河岸和邻屋，重新打开工程并导出回读。
  2. 从三维曲线生成屋顶，修改源曲线和材料，再手改局部，核对关联更新与撤销。
  3. 复用窗/柱构件，修改所有实例，再独立修改一处。
  4. 在密集场景中连续拖动与绘制，记录输入到可见反馈、内存与修改范围；不得只用内部计算耗时证明跟手。
  5. AI 从零建造后交给人继续修改，所有自由操作不要求预设模板。
  6. 安装对应桥接，在实际 Java 实例中读取、施工、回读和撤销；编译验证与实际游戏验证分别记录。
